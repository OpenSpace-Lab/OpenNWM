# LAM

Four LAM variants share the original losses, data sampling, and evaluation protocols. Run commands from the repository root.

## Setup

Follow the [installation and path setup](../README.md#environment-setup), then load paths in each terminal:

```bash
source .env
```

Commands support `--help` and path overrides such as `--data-root` and `--split-root`.

## Data

```text
$NWM_DATA_ROOT/
├── recon/<trajectory>/{0.jpg, 1.jpg, ..., traj_data.pkl}
├── sacson/<trajectory>/{0.jpg, 1.jpg, ..., traj_data.pkl}
├── scand/<trajectory>/{0.jpg, 1.jpg, ..., traj_data.pkl}
└── NavAnywhere/<dataset>/<trajectory>/{0.jpg, 1.jpg, ...}

$NWM_SPLIT_ROOT/<recon|sacson|scand>/<train|val|test>/traj_names.txt
```

`traj_data.pkl` contains frame-aligned `position` and `yaw`; each manifest line is a relative trajectory directory. NavAnywhere needs numbered frames only. Set `NWM_NAVANYWHERE_ROOT` or `--navanywhere-root` for a separate mount. Frames are center-cropped to 4:3 and resized to 240×320.

LAM and NWM share the splits generated by `setup_paths.py`, or existing splits supplied by the user. Training reads `train`; checkpoint selection uses `val`; final evaluation uses `test`. Keep the same splits when reproducing an experiment. To override validation sources, pass `--eval-config /data/val.yaml`:

```yaml
source_specs:
  - data_root: /data/navigation/recon
    split_manifest: /data/splits/recon/val/traj_names.txt
    display_name: RECON
    waypoint_spacing: 0.25
```

## Training and Resume

| Variant | Model | Default data recipe |
| --- | --- | --- |
| 1 | ActionOnlyLAM | `legacy`: RECON, HuRoN, SCAND |
| 2 | PixelLAM | `navanywhere`: 13 NavAnywhere sources + 3 action sources |
| 3 | DINOFeatureLAM | Same sources; online DINOv3 features |
| 4 | PixelActionLAM | Same sources; original calibrated action loss weight |

```bash
python run.py lam train --variant 2 --run-dir "$OPENNWM_WORK_ROOT/runs/lam-pixel" --devices 1
# Select another --variant; use --profile navanywhere15 for 15 sources.
# Use --profile legacy for the original three action sources.

python run.py lam train --variant 2 --run-dir "$OPENNWM_WORK_ROOT/runs/lam-pixel" --devices 1 --resume
# Resume a specific full Lightning checkpoint with --resume /weights/model.ckpt.
```

Each run saves `config.yaml`, fixed `validation_pairs.json`, TensorBoard logs, and reconstructions. By default, validation and `checkpoints/latest.ckpt` run every 1,000 steps; `best.ckpt` updates on lower validation loss. Periodic `step=*.ckpt` checkpoints are saved every 10,000 steps, keeping the latest three. All checkpoints include training state, and validation/save also run at completion.

Override these settings with `--eval-every`, `--save-every`, `--periodic-every`, and `--keep-periodic` (`0` keeps all periodic checkpoints). Validation reports model-specific losses, PSNR/SSIM, action MAE, or feature similarity.

`--batch-size` is per GPU. Other overrides include `--max-steps`, `--lr`, `--precision`, `--grad-accum`, and `--config override.yaml`. `--dry-run` writes configuration only. Multi-node runs support `--nodes`, `--node-rank`, and `--master-addr`. TensorBoard is local by default; enable WandB with `--wandb project_name`.

## DINOv3 Weights

Variant 3 requires the frozen DINOv3 ViT-L/16 teacher. Paths come from `.env`; skip cloning if the repository already exists. Other variants do not need DINOv3.

```bash
mkdir -p "$(dirname "$DINO_REPO_PATH")"
git clone https://github.com/facebookresearch/dinov3.git "$DINO_REPO_PATH"
git -C "$DINO_REPO_PATH" checkout 346f38fee679c56a6888f91c51670fae61d364e0
python run.py lam prepare-dino --output "$DINO_WEIGHTS_PATH"
python run.py lam train --variant 3 --run-dir "$OPENNWM_WORK_ROOT/runs/lam-dino"
```

Downloads resume automatically and reuse existing weights. For the `legacy` recipe, first generate a configuration with `--profile legacy --dry-run`, then precompute features:

```bash
python run.py lam precompute-dino \
  --base-config "$OPENNWM_WORK_ROOT/runs/lam-dino/config.yaml" \
  --cache-root "$OPENNWM_WORK_ROOT/cache/dino"
```

Train with `--profile legacy --dino-cache "$OPENNWM_WORK_ROOT/cache/dino"`. Validation and final evaluation still require the teacher repository and weights to extract features from validation images.

## Evaluation

```bash
python run.py lam eval all \
  --checkpoint "$OPENNWM_WORK_ROOT/runs/lam-pixel/checkpoints/best.ckpt" \
  --output-dir "$OPENNWM_WORK_ROOT/eval/lam-pixel" \
  --data-root "$NWM_DATA_ROOT" --split-root "$NWM_SPLIT_ROOT"
```

The default protocols are ID, ID-CD, OOD, and OOD-CD. Training domains are RECON/HuRoN/SCAND; OOD uses TartanDrive (`tartan` data directory, `tartan_drive` split directory). For GO Stanford, pass `--config lam/config/navigation_eval_go_stanford.yaml`.

Evaluation preserves the original action, pixel, and feature metrics, controls, and bootstrap summaries. Outputs include `summary.md/json/csv` and per-sample results. Add `--num-visual 8` for reconstructions. Custom YAML files can specify sources and runtime options; CLI arguments take precedence, followed by data-path environment variables.

Rerunning resumes saved batches. Use a new output directory when the checkpoint or configuration changes. `prepare-manifest` fixes sampling so models can share `--manifest`. LPIPS weights download to `LAM_EVAL_ASSET_ROOT`; prepare them before offline evaluation:

```bash
python run.py lam eval prepare-assets --asset-root "$LAM_EVAL_ASSET_ROOT"
```

`--disable-lpips` is for debugging and omits part of the full metric set. See [NWM](../nwm/README.md) for feature caches and world model training.

For development tests, install `"$LAM_PYTHON" -m pip install pytest==9.1.1`, then run `"$LAM_PYTHON" -m pytest lam/tests tests/test_lam_resume.py -q`.
